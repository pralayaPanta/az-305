> [!faq]- Show Answer & Explanation
> **Answer: A** — When connecting an Azure VNet to on-premises networks via Site-to-Site VPN, **address spaces must never overlap**. Because on-premises uses `172.16.0.0/16`, Azure must use a non-overlapping private RFC 1918 range (such as `10.1.0.0/16`). `Subnet1` (`10.1.1.0/24`) easily accommodates 30 VMs (251 available IPs), and `GatewaySubnet` requires at least `/27` (`/28` is Microsoft minimum, `/27` recommended).
