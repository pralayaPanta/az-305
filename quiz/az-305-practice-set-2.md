> **Answer: A** — Microsoft Entra External ID (or B2B direct federation) enables external federation with third-party identity providers such as Google (OAuth/OIDC) and Okta (SAML/WS-Fed), allowing external users to authenticate using their enterprise credentials without custom auth plumbing. App Proxy (B) is for accessing on-premises applications. Local SQL credentials (C) defeat single sign-on. PTA (D) is strictly for hybrid AD DS sync.

### Question 50

You are designing an API architecture for an insurance company. You need to protect 10 backend Azure Container Apps exposing REST endpoints. Requirements:
- **External mobile apps must authenticate using Microsoft Entra ID tokens.**
- **The backend Container Apps must run on private virtual network subnets with no public IPs.**
- **Traffic must be inspected for common web vulnerabilities (SQLi, XSS) before reaching the API gateway.**

**What architecture should you recommend?**

A) Azure Application Gateway (WAF v2) in the public subnet → Azure API Management (Internal VNet mode) → Azure Container Apps (Internal VNet environment)  
B) Azure Front Door Standard → Public IP on Azure Container Apps  
C) Public Azure API Management instance with basic throttling rules only  
D) Azure Network Watcher with NSGs on all subnets

> [!faq]- Show Answer & Explanation
> **Answer: A** — This is the standard enterprise reference architecture for secure APIs: Application Gateway WAF v2 sits on the public edge providing OWASP Top 10 web protection (SQLi, XSS, TLS termination), then forwards requests to an internal APIM instance deployed inside the VNet. APIM validates Entra JWT tokens, handles routing/rate-limiting, and sends clean traffic to backend Container Apps residing entirely in internal subnets. Front Door Standard (B) lacks WAF capabilities and Container Apps require private isolation.
