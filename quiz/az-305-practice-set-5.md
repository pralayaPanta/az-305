### Question 13

An application processes financial transactions and stores transactional records in Azure Cosmos DB (NoSQL API).
- Write operations take place across two Azure regions: East US and West US.
- Compliance regulations require that no two concurrent client updates can overwrite the same document without checking whether the document has been modified since it was last read.

What feature should you use to implement this optimistic concurrency control?

A) The `_etag` system-generated property passed in the `If-Match` request header  
B) Pessimistic document locking via SQL API stored procedures  
C) Change Feed with distributed locks in Redis  
D) Strong consistency across both regions  

> [!faq]- Show Answer & Explanation
> **Answer: A** — Azure Cosmos DB supports **Optimistic Concurrency Control (OCC)** using the internal **`_etag`** property. When updating or deleting an item, the client passes the previously read `_etag` in the `If-Match` HTTP header. If another client has updated the document in the interim, the `_etag` will not match and Cosmos DB rejects the transaction with HTTP status 412 Precondition Failed, preventing accidental data overwrites.
