### Question 1

Your company has two divisions operating in separate Microsoft Entra ID tenants: `contoso.com` and `fabrikam.com`.

### Question 4

Your enterprise has an Azure root management group named Tenant Root Group and a child management group named MG1.
You have the following resource hierarchy:
- Subscriptions Sub1 and Sub2 reside inside MG1.
- Sub1 contains resource groups RG1 and RG2. Sub2 contains RG3.
- Security group Group1 is assigned the **Virtual Machine Contributor** role on MG1.
- Security group Group3 is assigned the **Contributor** role on Tenant Root Group.
- User3 is explicitly assigned the **Contributor** role directly on Sub1.

Evaluate the following statements (True/False):
1. User3 can create virtual machines in RG1 and RG2.
2. Members of Group1 can create storage accounts in Sub1.
3. Members of Group3 can create virtual networks in RG3.

A) 1 = True, 2 = True, 3 = False  
B) 1 = True, 2 = False, 3 = True  
C) 1 = False, 2 = False, 3 = True  
D) 1 = True, 2 = True, 3 = True  

> [!faq]- Show Answer & Explanation
> **Answer: B (1 = True, 2 = False, 3 = True)**
>
> - **Statement 1 is True:** User3 has the Contributor role at the Sub1 scope. Azure RBAC roles are inherited downward through the hierarchy. Sub1 Contributor grants full resource creation permissions in all child resource groups (RG1, RG2).
> - **Statement 2 is False:** Group1 only has the **Virtual Machine Contributor** role on MG1. This role permits managing virtual machines, but does **not** grant rights to create or manage storage accounts.
> - **Statement 3 is True:** Group3 has the **Contributor** role at the **Tenant Root Group** level. Because Tenant Root Group is the ancestor of all management groups, subscriptions, and resource groups, Contributor permissions inherit down to Sub2 and RG3.

- Security directives require end-to-end data link layer encryption over the physical fiber links connecting enterprise edge routers directly to Microsoft's Enterprise Edge (MSEE) routers.
- Encryption must operate at Layer 2 (data link layer) to deliver line-rate 100 Gbps throughput without packet fragmentation, MTU reduction, or CPU tunneling overhead.
- Encryption keys must be stored and managed securely within Azure Key Vault.

Which encryption technology should you recommend?

A) Point-to-point **MACsec (IEEE 802.1AE)** encryption configured on the ExpressRoute Direct ports with keys stored in Azure Key Vault  
B) Site-to-site IPsec VPN tunnel running over ExpressRoute Microsoft Peering  
C) Azure Bastion host with TLS 1.3  
D) Application Gateway with mutual TLS (mTLS)  

> [!faq]- Show Answer & Explanation
> **Answer: A** — **MACsec (IEEE 802.1AE)** provides Layer 2 hardware-based line-rate encryption across the physical Ethernet connections between on-premises edge routers and Microsoft Enterprise Edge (MSEE) devices on **ExpressRoute Direct**. It operates at wire speed (10 Gbps / 100 Gbps) without MTU penalties or CPU tunneling overhead, and securely fetches pre-shared keys (CAK/CKN) stored in Azure Key Vault. IPsec (B) operates at Layer 3, adds encapsulation overhead, and cannot achieve 100 Gbps line rate on a single tunnel.

### Question 47

A healthcare provider connects to Azure using a standard partner-provisioned 1 Gbps ExpressRoute circuit with private peering.
Requirements:
- Regulatory compliance mandates network layer encryption in transit for all traffic flowing between the on-premises datacenter and Azure virtual machines.
- Because the connection uses standard partner ExpressRoute (not ExpressRoute Direct), Layer 2 MACsec is not supported.
- Traffic must remain strictly on the private ExpressRoute circuit and must never traverse the public internet.

Which architecture should you recommend?

A) Deploy an Azure Virtual Network Gateway (VPN type) in the VNet and establish a site-to-site **IPsec/IKE VPN tunnel over ExpressRoute Private Peering** using private IP addresses  
B) Enable MACsec encryption on the partner ExpressRoute circuit  
C) Deploy Azure Front Door with end-to-end SSL encryption  
D) Configure Virtual Network Service Endpoints with Microsoft Peering  

> [!faq]- Show Answer & Explanation
> **Answer: A** — For standard ExpressRoute circuits where MACsec is unavailable, Microsoft supports deploying an Azure VPN Gateway to establish a **site-to-site IPsec/IKE tunnel over ExpressRoute Private Peering**. By peering the VPN gateway with the on-premises VPN device using private IP addresses, all traffic is encrypted with IPsec before leaving the network edge, traversing the private ExpressRoute circuit without touching the public internet.

### Question 48

An enterprise operates a dynamic cloud environment running virtual machines, Azure App Service Premium v3 plans, Azure Container Instances (ACI), and Azure Dedicated Hosts.
Requirements:
- The finance team wants to commit to a consistent hourly compute spend ($60/hour) for a 3-year term to achieve discounts up to 65%.
- Application teams frequently refactor workloads: migrating between VM families (e.g., from D-series to E-series), switching OS types, moving workloads between regions, and containerizing VM apps into App Service or ACI.
- The discount must apply automatically across all these compute services, regions, and instance families without requiring manual reservation exchanges.

Which Azure financial commitment model should you recommend?

A) Azure Savings Plan for Compute  
B) Standard Azure Reserved Virtual Machine Instances (RI)  
C) Spot Virtual Machine Scale Sets  
D) Pay-As-You-Go with Azure Hybrid Benefit  

> [!faq]- Show Answer & Explanation
> **Answer: A** — **Azure Savings Plan for Compute** is the most flexible discount commitment model. It provides automated savings (up to 65%) when committing to a fixed hourly spend for 1 or 3 years. Unlike Reserved Instances (B)—which are tied to specific VM families and regions—Savings Plans automatically apply across **Azure VMs, App Service Premium v3, Container Instances (ACI), Azure Container Apps, and Dedicated Hosts** across any region and VM series without requiring manual exchanges or modifications.

### Question 49

An enterprise cloud FinOps team needs to eliminate budget overruns caused by sudden, unexpected cloud spending spikes across 60 Azure subscriptions.
Requirements:
- The system must automatically analyze historical spending patterns and detect unusual spikes in daily resource consumption using machine learning algorithms.
- It must not require administrators to manually define static numerical cost thresholds.
- When an unexpected cost surge is detected, automated email notifications containing the impacted resources and root cause must be dispatched to the FinOps team within 24–36 hours.

Which Azure Cost Management feature should you configure?

A) **Cost Anomaly Detection** alerts in Azure Cost Management  
B) Azure Budgets with fixed percentage alert thresholds  
C) Azure Monitor metric alerts tracking VM CPU utilization  
D) Azure Advisor weekly cost recommendation digests  

> [!faq]- Show Answer & Explanation
> **Answer: A** — **Cost Anomaly Detection** in Azure Cost Management uses platform machine learning to evaluate historical daily spend trends and automatically identify unusual cost spikes without requiring manual threshold configuration. When an anomaly is detected, Azure Cost Management generates an anomaly alert and sends an email notification detailing the subscription, resource group, and resource types causing the deviation. Azure Budgets (B) require manual fixed threshold limits. Advisor (D) recommends rightsizing, not daily anomaly alerts.

### Question 50

An enterprise purchased a 3-year Azure Reserved Virtual Machine Instance (RI) for 80 Standard_D16s_v5 virtual machines, scoped exclusively to `Subscription-Alpha`.
- Following an architectural refactoring, 30 of the D16s_v5 virtual machines in `Subscription-Alpha` were permanently decommissioned.
- Simultaneously, another department under the same enterprise billing enrollment deployed 30 Standard_D16s_v5 virtual machines in `Subscription-Beta`.
- Cost analysis reveals that `Subscription-Alpha` has 30 unused reservation instances (37.5% wasted capacity), while `Subscription-Beta` is paying full Pay-As-You-Go on-demand rates for identical VM sizes.
- You need to eliminate the wasted spend immediately without canceling the reservation, incurring financial exchange fees, or redeploying any virtual machines.

What administrative action should you take in the Azure portal?

A) Update the Reservation scope from Single Subscription (`Subscription-Alpha`) to **Shared Scope** (or Management Group scope) encompassing both subscriptions  
B) Cancel the reservation and purchase a new 3-year reservation for `Subscription-Beta`  
C) Delete the virtual machines in `Subscription-Beta` and redeploy them in `Subscription-Alpha`  
D) Submit an Azure Support ticket requesting a manual billing credit transfer  

> [!faq]- Show Answer & Explanation
> **Answer: A** — Azure Reserved VM Instances allow changing the **Reservation Scope** at any time without fees, penalties, or resetting the commitment term. By changing the scope from Single Subscription (`Subscription-Alpha`) to **Shared Scope** (or a parent Management Group scope), Azure billing automatically applies the 30 unused reservation slots to eligible matching VM instances running in `Subscription-Beta`, immediately eliminating wasted capacity and optimizing costs. Canceling (B) incurs annual refund limits and administrative delays.
